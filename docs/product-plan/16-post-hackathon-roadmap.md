# 16. 黑客松后路线图

## 路线图原则

黑客松 Alpha 证明完整链路后，后续路线图应围绕真实试用质量展开：更稳定的证据链、更可靠的任务执行、更好的团队协作和更可复盘的决策学习。不要过早扩展到所有决策类型和企业级平台能力。

## P0 已建立的质量基线

72 小时 Hackathon Prototype Slice 已要求：核心命题的引用支持度人工核验、支持/反对方向检查、确定性沙盘 fixture 验证、因果边 provenance、归一化与翻转条件测试、`live/cached/fixture` 诚实标识。这些不是黑客松后才首次实现的能力。

黑客松后要做的是把单案例质量基线扩展为多案例评估集、统计校准和真实复盘数据，而不是首次开始验证系统是否可信。

## 进入路线图前的继承条件

活动后的所有开发继续继承 OpenAPI 单向生成、CCR、CSRF/SSRF、请求预算、唯一 write owner 和 asset authorization 记录；不得在 P1 重新引入手写 DTO、任意 MCP URL 或未经确认的参考源码。

## 2 周：从演示 Alpha 到可试用 Alpha

目标：让 3 到 5 个真实团队可以用 Ludus 跑一次高风险产品或市场决策。

产品任务：

- 打磨首个场景模板：产品方向和细分市场进入。
- 增加案例导入：粘贴会议纪要、访谈摘要、链接和已有报告。
- 增加报告修订：用户可要求局部重写某章节，并保留版本差异。
- 增加证据确认流程：用户可标记来源可信、存疑或不适用。
- 增加复盘提醒：到期前提示补充实际结果。

工程任务：

- 加固 Postgres 备份、恢复、连接池和租户隔离策略，并评估托管 Postgres 服务。
- 将 `DecisionCase` schema 固化为 Alembic 迁移、Pydantic 服务端校验和 Zod 前端边界校验。
- 完善任务恢复：Worker 重启、任务超时、手动重试。
- 加固 P0 已有认证与 Workspace 隔离，增加会话管理、邀请机制和安全审计。
- 建立演示和试用数据隔离。

质量任务：

- 建立 10 个预置测试案例，覆盖市场进入、产品方向、定价和渠道。
- 给报告质量门增加自动检查：引用缺失、条件缺失、反方缺失、过期资料。
- 将 P0 单案例沙盘人工验收扩展为 10 个案例的标注评估：节点是否合理、边是否过度推断、翻转条件是否稳定。

成功指标：

- 真实团队完成 5 个 `DecisionCase`。
- 80% 的报告主要判断有可追溯证据。
- 70% 的用户认为系统帮助他们发现至少一个关键假设或反方风险。

## 6 周：试用产品 Beta

目标：让 10 到 20 个团队在真实工作流中使用，形成可复盘决策库。

产品任务：

- 增加决策模板库：定价、关键招聘、渠道选择、融资节奏。
- 增加团队协作的轻量能力：评论、@负责人、只读分享链接。
- 增加历史案例检索：根据问题、行业、假设和证据搜索过往决策。
- 增强沙盘版本对比：在 P0 两版本比较基础上增加多分支并排、跨复盘期差异归因和可分享比较视图。
- 增加复盘报告：实际结果、假设命中、偏差原因、下次建议。

工程任务：

- 引入后台任务队列或可靠工作流组件，替代纯 DB polling 的部分职责。
- 增加对象存储，用于报告、PDF、导入文件和证据快照。
- 增加向量检索或全文检索，支持历史决策和证据检索。
- 增加 LLM 调用观测，记录 prompt 版本、模型、耗时、失败原因和成本。
- 增加导出格式：Markdown、PDF、HTML 分享页。

质量任务：

- 将 P0 核心命题核验扩展为版本化报告评估集，覆盖引用准确性、建议边界、反方质量和可执行性。
- 对 Agent 输出做回归测试，避免 prompt 调整导致结构漂移。
- 对沙盘算法做数值稳定性测试和 UX 误解测试。

成功指标：

- 20 个真实决策项目创建。
- 10 个项目由授权人类完成 signoff，保存不可变最终决定和复盘日期。
- 报告生成成功率超过 90%。
- 沙盘编辑后保存率超过 50%。

## 3 个月：真实试用产品

目标：成为创业团队和创新团队的标准决策工作台，支持真实组织内的多项目使用。

产品任务：

- 完善团队空间、角色权限和分享审计。
- 增加组织级决策库和复盘学习视图。
- 增加连接器：Google Drive、Notion、Slack、网页链接和本地文件导入。
- 增加多决策组合视图：资源冲突、战略主题、风险集中度。
- 增加决策质量评分：证据充分性、假设清晰度、反方强度、复盘完成度。

工程任务：

- 将 P0 Workspace 隔离升级为生产级多租户加固：更细 RBAC、分享审计、隔离验证和组织级策略。
- 生产级队列、对象存储、日志、指标和告警。
- 加密敏感数据，支持导出和删除。
- 引入评估和观测平台，追踪报告质量和模型成本。
- 支持模型提供商切换和企业 API Key 配置。

方法论任务：

- 为不同行业建立可编辑框架，不做固定答案库。
- 建立来源可信度和过期规则的领域配置。
- 建立复盘知识库，把失败假设和成功模式转为后续提示。
- 建立“反方审查”最佳实践模板，避免流于形式。

成功指标：

- 5 个以上团队持续使用 4 周。
- 50 个以上 `DecisionCase` 创建。
- 30% 以上项目完成复盘。
- 用户能从历史复盘中复用假设、证据或风险模式。

## 仍应推迟的能力

即使到 3 个月，也应谨慎推进：

- 精确预测未来和自动决策执行。
- 深度连接生产业务系统并自动修改数据。
- 高复杂度多 Agent 市场宣传。
- 大而全行业知识库。
- 过早复杂权限矩阵和审批流。

这些能力只有在核心决策档案、证据链、报告和复盘被真实用户验证后，才值得进入产品主线。

## 产品北极星

长期北极星不是报告数量，也不是 AI 回复数量，而是“被复盘的高质量决策数量”。一个高质量决策必须有明确问题、证据、假设、反方、条件化建议、行动项、领先指标和复盘结果。Ludus 的路线图应持续优化这个闭环。
