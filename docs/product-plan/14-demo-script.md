# 14. 演示剧本

## 演示目标

5 分钟内让观众看到 Ludus 的核心区别：它不是聊天机器人，也不是一次性报告生成器，而是围绕同一个 `DecisionCase` 连续完成讨论、证据、报告、沙盘和复盘记录。

开场话术：**“Ludus — 预见未来，保障您的事业。这里的预见不是预测一个确定未来，而是在投入之前看见关键假设、影响路径和决定何时应该改变。”**

## 预置案例

案例：`资金与研发资源有限的球形机器人项目，应该优先进入救援市场，还是家庭服务市场？`。

背景：

- 项目已有可运行的球形机器人原型，但续航、载荷和复杂地形能力尚未完成市场化验证。
- 救援机构有远程侦察需求，家庭用户可能有巡检和陪护需求，但两边的付费与采购证据都不完整。
- 团队资金与研发资源有限，只能优先验证一个方向。
- 目标是在现金窗口内找到需求真实、技术可交付且责任边界可接受的市场路径。
- 硬约束是不能同时启动两个市场方向的完整产品化，且试点投入不能突破现金窗口。

预置资产严格分层：

- `fixtures/spherical-robot/seed/`：演示输入与已确认档案，只用于幂等 seed。
- `fixtures/spherical-robot/external/`：deterministic model/search/crawl 外部响应，是用户显式 fixture 降级时唯一可加载目录。
- `fixtures/spherical-robot/expected/`：结构化报告、图、三情景、决定和 Review 的回归期望，只供 verify 比较，运行时不得读取。
- 预生成 HTML/PDF 和完整录屏只作现场恢复资产，必须标记为历史/备用；正常演示展示本次 Run 生成的 HTML/PDF，不冒充实时结果。

## 5 分钟剧本

### 0:00-0:40 创建项目

演示动作：

1. 登录后直接进入日常问答，打开案例列表，选择演示 Workspace、球形机器人主体和 `seed_demo.py` 幂等创建的唯一 seed Case；快速展示“新建案例”入口但不在 fixture 主链新建。
2. 在 Case 对话中确认决策问题：`球形机器人应该优先进入救援市场还是家庭服务市场？`
3. 输入简短背景并从 P0 的 PDF/TXT/Markdown 文件入口上传一份 TXT 演示材料；文件形成待质检 RawArtifact。

讲述重点：

- 系统先形成决策项目，而不是直接回答。
- 第一轮输出是澄清问题和结构化档案入口。
- 用户不需要预先选择市场方向模板，决策类型由系统从对话中归纳。
- 案例列表/创建和最小文件入口是真实 P0，不是演示脚本外的占位页面。

### 0:40-1:30 决策讨论模式

演示动作：

1. 展示 AI 的澄清问题。
2. 回答目标、硬约束和已有证据。
3. 打开右侧“待确认变更”，把一条候选“事实”改为“假设”，再确认本轮 `CandidateRevision`。
4. 展示确认后的 `DecisionCase` 面板与 `ArgumentTree`：5W1H、目标、约束、事实、假设、未知项、选项、支持/反对理由、证据连接和新版本事件。

讲述重点：

- 事实、假设、判断和偏好被分开。
- 对话结果先进入候选区，只有用户确认后才写入版本化档案。
- 系统不暴露内部思维，只展示可审计对象。

### 1:30-2:40 深度报告模式

演示动作：

1. 点击“分析这个问题”，选择“完整战略分析”。
2. 展示 Analysis Charter：系统推荐 `hardtech-market-direction@1.1.0`，说明理由、边界、缺口、快照和预算。
3. 用户确认 Charter，指出可见的 Run 取消动作但主金路径不点击；展示任务进度事件：检索、因子结论、反方审查、综合、校验。
4. 展开 Agent Task List 和一条 Tool Call：显示 Research/Critic/Synthesis/Validation 状态、工具用途和产物摘要，不展示内部思维。
5. 展示来源状态：Exa 找到候选资料，Firecrawl 抓取高价值页面；若使用缓存，明确显示 `cached`。
6. 切到已生成报告。
7. 展示一页简报：建议、条件、阈值、退出条件、领先指标、复盘日期。
8. 展开“五项战略透镜”：快速扫过 Porter、Pre-Mortem、Counterparty、Scenario、Meadows 的校验状态，再打开一条 Pre-Mortem 风险，展示它如何改变退出条件；随后点击其引用和反方审查。
9. 预览本次 HTML，下载本次 PDF；说明 PDF 失败时 HTML 仍可用并可重试。

讲述重点：

- 报告不是一次性作文，而是从证据、假设、反方和质量门生成。
- 五项能力不是通用 Prompt 中的五个名词：它们各自有 schema、独立产物、来源引用和行为验收，缺失任一项时 full 报告不能正式发布。
- 用户只选择分析深度，系统负责方法路由；确认后方法版本和范围不可静默改变。
- Research/Critic/Synthesis/Validation 是隔离上下文、Prompt、产物、预算和事件的 Ludus 编排角色；P0 可以共用 DeepSeek V4 Pro，不宣称是四个独立基础模型。
- 运行中来源冲突或已授权 Provider 恢复可通过结构化 resolution 继续；改变预算、材料、方法或目标必须创建 replacement Charter 和新 Run，冻结契约不会被“继续”按钮绕过。
- 建议是条件化的：满足采购周期和技术门槛时先做救援试点，否则继续研究，不直接全面产品化。
- PDF 和 HTML 来自同一个结构化报告对象。

### 2:40-4:10 决策沙盘模式

演示动作：

1. 点击“生成沙盘”，先看到当前条件化建议和三个最脆弱条件，不先展示完整因果图。
2. 选择“采购周期”，说明它是不可控外部因素、当前基线和证据状态；将其调整为 14 个月并运行压力测试。
3. 展示结果：救援优先建议是否保持、翻转阈值、触发的现金硬约束，以及“采购周期 → 首个回款 → 现金安全度 → 救援策略”的关键影响路径。
4. 点击“生成验证行动”，形成“在两周内验证目标机构实际采购周期”的候选行动；再将当前测试保存为“采购周期压力测试”实验分支。
5. 点击“展开完整模型”，定位刚才的高亮路径；确认一个高影响节点，确认一条有依据的边，否决一条缺少依据的边，再保存首个正式图版本。
6. 切换“采购延迟但技术达标”情景，展示早期预警信号以及当前救援优先策略被推翻。
7. 简要展示版本比较和非破坏性回滚；压力测试分支和历史版本仍保留。

讲述重点：

- 沙盘不是预测未来，而是帮助决策人判断当前建议在什么条件下仍成立或应该改变。
- 用户先完成一次有业务含义的压力测试，需要时再展开完整模型检查依据，不必先成为因果建模专家。
- AI 生成的路径可以被检查、否决、保存为实验或转为验证行动，不会直接修改正式决定。

### 3:35-4:10 添加一个现场因素

1. 主持人从压力测试进入“完整模型”，点击“添加影响因素”。
2. 输入：“地方预算审批稳定性会影响采购周期。”
3. 系统生成因素候选，将其标记为 `external`、`uncontrollable`、`assumed`，并明确提示“待验证”。
4. 系统建议一条到采购周期节点的关系；主持人检查方向、强度、延迟与理由后确认。
5. 因素与关系进入工作副本，页面在 1 秒目标内显示实验预览：高亮“预算审批稳定性 → 采购周期 → 首个回款 → 现金安全度”的变化路径，并说明建议保持、收窄、翻转或证据不足。
6. 主持人说明：“这是实验预览，不是正式结论。”随后把修改保存为命名实验分支；若要形成正式结果，仍需保存不可变图版本、完成确认并主动运行 formal simulation。

该段演示不得把未证实因素说成事实，也不得让系统自动确认关系或自动签署决定。
### 4:10-5:00 请求签署并由人类保存最终决定

演示动作：

1. 打开最终决定抽屉。
2. 选择“优先推进救援市场试点”。
3. 确认条件、阈值、退出条件、行动项、领先指标和复盘日期。
4. 保存决定，打开 Review 区分别记录建议采纳、执行偏差、决策过程、外部变化、现实结果、假设验证和下一轮改变，再刷新并重新打开核对来源版本。
5. 先创建 SignoffRequest，再以授权人类身份签署；回到案例列表显示状态 `decided`，并强调系统不能自动完成该转换。

讲述重点：

- 系统把决定和结构化复盘保存下来，并明确区分坏决策过程、执行偏差、外部冲击和结果质量。
- P0 保存和读取 Review；自动到期提醒在活动后实现。
- 几周后团队可以回看当时证据和假设，判断是否该调整。

## 自由输入案例

用于展示系统不是完全静态演示。建议输入：

```text
我们是一家面向制造业的 SaaS 公司，正在考虑是否进入欧洲市场。团队担心销售周期、合规成本和本地伙伴能力。请帮我们组织这个决策。
```

自由输入演示只承诺：

- 创建项目。
- 生成澄清问题。
- 初步形成 5W1H、目标、约束、假设和未知项。
- 可运行带“非正式方法输出”标识的快速分析，或切回预置深度报告演示。

该案例不匹配 P0 唯一正式方法包，只承诺聊天、结构化档案和带“非正式”标识的快速分析。聚焦研究、完整战略分析、正式 PDF 和正式沙盘必须显示当前不支持，不能用通用 Prompt 冒充正式结果。

投资项目批量筛选是活动后的第二方法包，不在本次现场演示、备用录屏或 72 小时验收中出现。

## 降级方案

| 故障 | 主持人动作 | 展示内容 |
|---|---|---|
| 模型在重试/备用配置后仍不可用 | 系统解释影响，用户点击“加载 deterministic fixture” | fixture provider 提供确定性外部输入，Worker、质量门和后续链路继续真实运行并持续显示 `fixture` |
| 搜索失败 | 切换“使用缓存证据” | 证据包和事件标注缓存 |
| PDF 失败 | 保留 HTML，PDF Export 显示 `failed`，修复后重试 | 报告内容不丢失，不把历史 PDF 冒充本次导出 |
| 沙盘生成失败 | 显示可读错误并恢复图生成；若已有历史图，只能作为明确标识的历史结果只读展示 | 不加载预置图冒充本次生成 |
| 网络断开 | 保持本地 Postgres、状态机和沙盘运行并加载显式标记的静态 fixture | 完整离线演示，外部输入标记 `fixture` |
| SSE 不稳定 | 刷新任务页或展示事件列表 | 进度可恢复 |

## 现场演示检查清单

除原检查项外，必须保存当前容量档、OpenAPI drift check、DeepSeek 能力 probe、CSRF/SSRF/跨租户测试和 live/fixture 来源截图。若任一发布门失败，演示只能使用明确标记的离线模式并说明限制，不能冒充正式 live 链路。

演示前 30 分钟检查：

- 本地服务器可启动。
- 预置案例可加载。
- 数据库已 seed。
- Python 3.12、uv、Docker daemon/Postgres 与 Playwright preflight 已通过。
- live 验收的 DeepSeek 官方 API probe 已通过：默认 `provider=deepseek`、请求 `deepseek-v4-pro`，并记录 API 返回版本/模型标识；这是 72 小时计时前 Gate 0 硬门。
- 在通过 live 验收后，另做主动断开 Key/网络的备用彩排，验证显式 fixture 路径；该彩排不替代 probe，也不计为 live 成功。
- `ways/hardtech-market-direction/1.1.0` 已校验安装，runtime method-pack 哈希一致。
- 搜索工具可用；若不可用，缓存证据路径已测试。
- Exa、Firecrawl 和 Tavily 连接器状态已检查，演示 Key 不出现在浏览器或日志中。
- 本次 Run 的 HTML/PDF 导出已测试；预生成 PDF 仅作明确标识的备用。
- Chrome/Playwright 依赖可用。
- 来自 Scenario Planning 的三个 confirmed 业务情景至少各运行一次，且至少一个能推翻当前策略。
- 浏览器缩放固定在适合投影的比例。
- 演示机器断网后仍能完成预置案例。
- live 路径优先完成过一次；fixture 只是最坏情况，不作为正常演示默认入口。
- 独立彩排已验证 Run cancel 后不发布正式产物，以及 Review 保存/刷新/读取；现场主链不取消当前 Run。

演示中避免：

- 让模型临场生成长报告。
- 把四个编排角色描述成四个独立基础模型。
- 声称沙盘能预测未来。
- 展示未通过质量门的报告作为正式结论。

## 备用讲述句

- “Ludus 的单位不是聊天轮次，而是版本化决策档案。”
- “系统把事实、假设、偏好和判断分开，所以团队能质疑每一步。”
- “这个建议不是无条件答案，它带有条件、阈值、退出条件和复盘日期。”
- “沙盘展示的是因果敏感性，不是未来预测。”
- “当模型或搜索失败时，系统保留证据和报告对象，不把失败伪装成成功。”

## 宣传与提交资产

72 小时内除现场演示外，还必须生成：

- 60-90 秒宣传录屏，使用预置案例，不等待实时长任务。
- 至少 6 张截图：日常问答、档案确认、分析任务书、证据质量、正式报告、因果沙盘。
- 一页产品说明和一张系统架构图。
- 一份完整金路径备用录屏。
- 不含 API Key、调试栏、个人信息和未通过质量门内容的发布素材。
