## Reason

P2-001 delivers doc-22 Postgres-backed login rate limiting inside the `case_api_data` write scope (`app/security/rate_limits.py` plus login wiring). The throttle table is declared on a deliberate module-local `MetaData` because canonical migrations belong to `contract_lead`; login intentionally fails closed (429 `REQUEST_RATE_LIMITED`) while the table is absent, making the canonical migration a release prerequisite rather than an optional follow-up.

## Accepted decisions

1. New Alembic revision `c4a1f0b2d9e7_add_login_rate_buckets.py` (down_revision `f850d361ee42`) creates `login_rate_buckets` column-exact with the Core Table in `app/security/rate_limits.py`: `bucket_key VARCHAR(64) NOT NULL`, `slice_start TIMESTAMPTZ NOT NULL`, `attempts BIGINT NOT NULL`, `PRIMARY KEY (bucket_key, slice_start)`. Downgrade drops the table (login returns to fail-closed).
2. `migrations/env.py` registers `rate_limit_metadata` alongside `Base.metadata` as target metadata so `alembic check`/autogenerate treat the throttle table as canonical instead of proposing a drop. The table intentionally stays off `Base.metadata` so QA's exact-table assertions over ORM models remain unchanged.
3. `.env.example` adds non-secret placeholders `AUTH_LOGIN_RATE_WINDOW_MINUTES=15`, `AUTH_LOGIN_RATE_IP_MAX_ATTEMPTS=20`, `AUTH_LOGIN_RATE_ACCOUNT_MAX_ATTEMPTS=5`, matching `AuthSettings` defaults.
4. No OpenAPI/TypeScript regeneration: `REQUEST_RATE_LIMITED` (429) already exists in the doc-10 security error table and the API surface shape is unchanged.

## Canonical impact

- `services/api/migrations/versions/c4a1f0b2d9e7_add_login_rate_buckets.py`: new (this change).
- `services/api/migrations/env.py`: target metadata registration (this change).
- `.env.example`: three `AUTH_LOGIN_RATE_*` placeholders (this change).
- No model/schema/API/event change; `packages/contracts/**` untouched.

## Deployment note and follow-ups

- Integration/deploy order: run migrations before (or together with) exposing login; a missing table yields uniform 429, unavailable-but-safe.
- Reverse-proxy client-IP policy (X-Forwarded-For) is a later deployment-hardening slice; the remaining doc-22 limits (mutation burst, connector/model budgets, signoff attempts) are later slices owned by case_api_data.
