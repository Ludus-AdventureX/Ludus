# CCR-20260724-SIM-01: Canonical simulation graph contract (graph aggregate, versions, scenario/strategy/score, simulation_runs frozen-reference FKs)

- Date accepted: 2026-07-24
- Base: main `4de362835f728ab155fc197b9f11b9ac248f2936` (live-verified at implementation start; migration head `d7e2a91c5b48`)

## Reason

The Task 12 deterministic engine landed contract-clean; graph persistence needed canonical wire types, ORM tables, and a linear migration owned by contract_lead. The engine consumes immutable GraphVersion/StrategyVersion/ScenarioVersion/ScoreDefinition inputs and SimulationRun already carries the frozen reference columns without FKs.

## Accepted decisions (with corrections)

1. Seven canonical Python enums in `app/types.py`: `GraphVersionStatus`, `EdgePolarity`, `FactorAuthorship`, `FactorEvidenceStatus`, `FactorControllability`, `GraphBranchStatus`, `ConstraintComparison`. Six become PostgreSQL enums; `ConstraintComparison` deliberately has no PG enum (it lives in score_definitions JSONB rules and is wire/service-validated). `NodeType` already exists and is reused; graph_nodes.node_type is a CHECK-constrained string so the PG enum count stays at six.
2. Eight new tables (not seven): `causal_graphs` (stable aggregate; current_graph_version_id is a service-validated pointer, no FK, to avoid a creation cycle), `graph_versions` (immutable; CHECK confirmed-requires-timestamp; NO confirmed partial unique index — multiple confirmed versions are the history model; branch_id service-validated to avoid circular FK with graph_branches), `graph_nodes` (business units persisted; `uq_graph_nodes_workspace_version_id`), `graph_edges` (same-version composite FKs for source/target; `uq_graph_edges_workspace_version_id`; strength and relationshipQualityScore separate), `strategy_versions`, `scenario_versions` (risk_tolerance forbidden; source_lens_artifact composite FK to strategic_lens_artifacts via the proven `(workspace_id, strategic_lens_artifact_id)` unique), `score_definitions` (adds `content_hash`), `graph_branches`.
3. Canonical wire types in `app/simulations/schemas.py`: `CausalGraph`, `GraphVersion` (+`GraphProvenanceRef`), `CausalNode`, `CausalEdge`, `StrategyVersion`, `ScenarioVersion` (+`ScenarioEarlyWarningSignal`; extra="forbid" rejects riskTolerance on the wire), `OptionOutcomeMapping`, `RiskWeight`, `ConstraintRule`, `ScoreDefinition`, `GraphBranch`. JSONB node/edge/option references are validated item-by-item by the service against the referenced graph version; the database does not resolve JSONB references.
4. Alembic revision `a3f8c2d47e19` (down_revision `d7e2a91c5b48`, single linear head). The four simulation_runs composite FKs (graph_version/strategy_version/scenario_version/score_definition, all tenant-scoped `(workspace_id, id)`, ON DELETE RESTRICT) are added via orphan preflight (abort with a clear error if any orphan exists) -> `ADD CONSTRAINT ... NOT VALID` -> `VALIDATE CONSTRAINT`; the migration never assumes simulation_runs is empty. Downgrade drops the eight tables and six new enums only; the pre-existing simulation_runs columns and shared `origin_mode` enum remain.
5. No API/router change, no `packages/contracts/**` change (wire types are not yet registered in the generated catalog; the graph API slice will register them under its own CCR step), no Task 12 engine change, no ways/web change. CCR-SIM-02 (persistence services/routes) is out of scope.
