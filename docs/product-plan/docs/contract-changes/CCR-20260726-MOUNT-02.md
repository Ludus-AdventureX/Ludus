## M5. M8 CSRF closure — NEW (behavioral adoption + canonical clarification, closes the MOUNT-01 M8 stop-report)

**Ruling — adopt the handoff r4 recommendation verbatim.** Under cookie-based session auth, authenticated unsafe writes are CSRF-exposed; the literal canonical scope ("Cookie mutation") was too narrow. This wave:

1. `app/analyses/routes.py`: all seven unsafe-write handlers (`resolutions`, `cancel`, charter create/PATCH/replacements/confirm, run create) now carry `Depends(require_csrf)` — SIM-02A parity. The dependency is parameter-level and declared after the workspace context, so unauthenticated callers still answer 401 before any CSRF 403; a router-level dependency was rejected because it would wrongly guard the SSE/status/lens `GET`s.
2. Safe reads (SSE events, run status, strategic-lenses list/item, all evidence GETs) remain CSRF-free.
3. Canonical text: §认证、session 与 CSRF is amended (SM1 below) to state that authenticated unsafe writes under cookie session auth carry CSRF — matching what SIM-02A and this wave actually enforce.
4. Wave regression: `test_mount02_csrf_enforcement.py` (7 parametrized 403 probes + safe-read control); disclosed connected maintenance adds the same-origin double-submit proof to the five analyses HTTP test fixtures (`test_analysis_http_handlers`, `test_qa_adversarial_mount02_r1b`, `test_analysis_sse_and_commands`, `test_analysis_idempotency_wire`, `test_analysis_amendment_durability`) — header/cookie/Origin only, zero assertion-semantics change.

**Residual (non-blocking, auth/security lane):** a platform-wide CSRF audit of any other cookie-authenticated unsafe writes outside the analyses/simulations surfaces (e.g. future cases/files/exports lanes) plus the `SameSite` posture review remain with the auth lane; this wave closes the analyses-surface item that MOUNT-01 stopped on.
