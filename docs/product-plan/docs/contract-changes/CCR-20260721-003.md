## Reason

## Accepted Decisions

### 1. 唯一 ID 命名

- Domain、Pydantic、OpenAPI、TypeScript 和 URL 参数统一使用 `decisionCaseId`、`analysisRunId`。
- 数据库列统一使用 `decision_case_id`、`analysis_run_id`。
- 禁止新增 `caseId`、`runId` wire alias；历史审计和迁移说明除外。

### 2. Source 生命周期

`SourceRecord` 和 `SourceSpan` 使用 `sourceScope: pre_run | run_frozen` 判别联合：

- `pre_run` 表达消息、Case 字段、上传文件和其他 Run 前来源，不得携带 `analysisRunId`；
- `run_frozen` 必须携带 `analysisRunId` 和冻结来源引用；
- `rawArtifactId` 仅在来源真实经过 RawArtifact 时存在，human input/case snapshot 不伪造 RawArtifact；
- Run 创建时把允许使用的 pre-run Source/Span 冻结为新的 run-scoped 记录，保留来源 ID 和 hash。

### 3. DeepAnalysis I/O

`DeepAnalysisRequest` 使用嵌套 `method: MethodVersionRef` 并包含 `analysisRunId`。`DeepAnalysisResult` 返回已持久化 artifact ID/hash，不内嵌第二套 Judgment/Dissent DTO。完整对象通过 Workspace/Run-scoped 读取接口获取。

### 4. 最小认证与权限

canonical schema 增加 `User`、`WorkspaceMembership` 和 `UserSession`：

- role 仅为 `owner | member`；
- capability 为 `contribute | review | sign | manage_connectors`；
- owner 默认拥有全部能力；member 由 membership 明确授予；
- JWT 的 `session_id` 必须映射可撤销 session；
- sign command 同时要求活动 session、Workspace membership 和 `sign` capability。

### 5. Signoff 原子内容

`SignoffRequest` 内嵌不可变 `SignoffPayload` 并保存 `payloadHash`。Payload 精确冻结 Case/Run/Report/Judgment/Dissent/Graph/Simulation 来源、系统建议或 abstain、人的选择、决定文本、条件、阈值、退出条件、行动项、领先指标、接受的 Unknown 和复盘日期。签署 body 只接受 `signatureStatement`、`payloadHash` 和一次 nonce。

### 6. 系统 abstain

系统建议使用判别联合：

- `{ kind: "option", optionId }`
- `{ kind: "abstain", reasonCodes, rationale }`

`fatal_fail`、质量门阻断或所有可选路径都不成立时必须使用 abstain；不得以空字符串伪装推荐。人仍可在知情情况下选择合法 option，但签署 payload 必须保留系统 abstain 与接受风险。

### 7. Simulation 可重放与数值语义

- `SimulationRun` 冻结 ScoreDefinition ID/版本、DecisionMakerProfile ID/版本、实际 riskTolerance、engineVersion、epsilon、maxSteps 和 inputHash；
- `ScenarioVersion.nodeShifts` 明确为归一化 delta；
- `relationshipQualityScore` 只影响解释质量、警告和发布门，不直接衰减因果 effect strength；
- formal 模式必须满足稳定性充分条件或返回非 converged，非 converged 不能改变正式建议；
- 敏感性优先使用节点配置步长，默认使用节点业务范围的 10%，而不是当前值的 ±10%。

### 8. 前端与 Look V7

`look/` 是最终视觉与关键交互参考，但不是生产运行时依赖。生产实现采用一次性、带版本/hash 的设计快照：

- `themes.css` 转换为集中 design tokens；
- `styles.css` 按 semantic/component token 拆入生产样式层；
- `index.html` 转换为 React 组件；
- `app.js` 只作为交互行为规格，禁止直接加载；
- 原型 Playwright/Axe 行为移植为生产 E2E。

canonical 主工作区固定为五个：问题 `workspace`、证据 `analysis`、判断 `report`、推演 `sandbox`、决定 `decision`。Review 使用可恢复 dialog/drawer，Case 选择使用 Project Drawer，空项目使用 `empty` 视图。公开主题 ID 精确为 `ink/ledger/vermilion/red/orange/yellow/green/cyan/blue/purple`，默认 `ink`。

- 完整五透镜 UI、PDF、完整图编辑、分支比较/回滚、BYOK UI、完整 Review、多文件格式和十主题以外的精修为 stretch；已完成的十主题 token 可接入，但不得阻塞金路径。
