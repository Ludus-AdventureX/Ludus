# CCR-20260725-SANDBOX-01 - Task 13 `sandbox-workspace` Slot and Bounded Shell Integration

- Date: 2026-07-25 (Asia/Shanghai)
- Status: **accepted**
- Change class: additive frontend shell contract and ownership clarification
- Affected task: Task 13 - Full-size sandbox interaction and graph versioning
- API / database / generated-contract impact: none

## Trigger

Task 13 canonically owns `apps/web/components/simulation/**`, but the frozen Task 11 Phase 0 shell had no sandbox mount slot. Without an additive slot, the Task 13 implementation could only remain disconnected or silently restructure the shell. The principal authorized a bounded slot-fill integration instead of either outcome.

## Decision

1. Add the frozen shell slot name `sandbox-workspace` with props `{ decisionCaseId: string }`.
2. `simulation_graph` remains the primary owner of `apps/web/components/simulation/**`.
3. `web_ux` is the secondary owner for exactly these integration paths:
   - `apps/web/components/shell/CaseViewRouter.tsx`
   - `apps/web/components/shell/PhaseSlot.tsx`
   - `apps/web/components/shell/views/SandboxView.tsx`
   - `apps/web/lib/shell/slotContracts.ts`
4. The secondary-owner change is limited to slot registration, prop pass-through, and replacement of the existing SandboxView placeholder. It MUST NOT restructure CaseShell, DecisionSpine, ProjectDrawer, DecisionHealthBar, other views, or other slots.
5. QA-owned tests may assert the additive slot and sandbox behavior; test changes do not transfer product-path ownership.
6. The original Task 13 branch remains auditable; no rebase, amend, force-push, or history rewrite is authorized.

## Canonical synchronization

- `agent-work-manifest.yaml`: Task 13 receives `secondary_owner: web_ux`, `contract_change_owner: contract_lead`, and the four exact `secondary_write_scope` paths.
