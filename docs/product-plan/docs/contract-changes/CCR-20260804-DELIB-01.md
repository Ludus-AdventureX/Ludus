# CCR-20260804-DELIB-01 — 推演议会（Deliberation Council）：因子持证人长程推演契约

**Status:** adopted (this commit)
**Lane:** codex/deliberation-ccr-r1（Contract wave；后续 backend/frontend/实机波次另立分支）
**Base:** main `29a8369`（证据抽屉修复 + 因果图 A+B 合并头）

## 动机

因果图 A+B 交付后，G 页具备确定性因子沙盘（report-factor-sandbox 引擎）与正式因果图画布，但用户目标形态——"每个智能体持有一个主观或客观因素，由一个主智能体组织推演，较及时地给出结果"——在现有合同中没有承载面：

1. 因子沙盘只收编检索阶段的客观证据因子；主观判断（决策人直觉、内部数据估计、对手反应判断）无合法入口。
2. 没有任何 LLM 参与者面：引擎是纯数值传播，无持证人视角、质证与异议。
3. 唯一的重推路径（Layer 3 深度重分析）是完整 focused run，分钟级且不带推演语义。

产品方明确要求完全体（不做裁剪），参照 MiroFish 的轮次编排形态，但**不采用**其群体涌现范式：Ludus 的推演必须是因子锚定、引擎裁决、可复现的（AGENTS §10"沙盘是可干预、可解释的因果决策模型，不是预测器"）。

## 裁决

### 1. 新领域对象（06-data-model.md 同步）

七个对象，全部 `workspace_id` 限定，属于沙盘域（不属于 AnalysisRun 状态机，不引入第二套正式分析任务队列）：

| 对象 | 关键内容 | 不变量 |
|---|---|---|
| `DeliberationRun` | id / decisionCaseId / status / roundSeq / maxRounds / factorSnapshotHash / originModes / 时间戳 | status ∈ `preparing \| running \| awaiting_user \| complete \| cancelled`；maxRounds ≤ 5；factorSnapshotHash 冻结创建时刻的客观基线（packets + influences）；主观因子为 append-only 介入留档（Human 署名），不在冻结哈希内 |
| `DeliberationFactor` | id / runId / provenance / label / strength / 来源引用 | provenance ∈ `objective \| subjective`；objective 必须引用源因子（sourceFactorId）；subjective 必须携带声明文本、初始强度、Human 署名（authorUserId），evidenceStatus 固定 ∈ `assumed \| unknown`——**永不 supported/conditional**；可选 `dossierAssumptionId` 引用档案假设 |
| `DeliberationRound` | id / runId / seq / kind / 状态 / 时间戳 | kind ∈ `opening \| challenge \| verdict`；seq 在 run 内严格单调 |
| `DeliberationMessage` | id / runId / roundId / speaker / speakerRef / kind / content / structuredPayload / ResponsibilityStamp / originMode / sourceOriginModes | speaker ∈ `witness \| moderator \| user`；witness 必带 speakerRef=factorId；kind ∈ `statement \| challenge \| rebuttal \| proposal \| intervention \| nomination \| verdict_summary`；每条发言携带责任戳（Human/Analysis/Unknown，§7） |
| `DeliberationProposal` | id / runId / proposerFactorId / kind / before / after / status / enginePreview | kind ∈ `factor_strength \| edge_validity \| new_factor`；status ∈ `pending \| accepted \| rejected`；**只有用户可决策**；enginePreview 是确定性引擎 `simulate()` 对该提议的预览计算（非模型输出） |
| `DeliberationNomination` | id / runId / rationale / targetDescription / status / confirmedFactorId | status ∈ `pending \| confirmed \| rejected`；**永不自动生效**：confirmed 前不得产生任何因子或数值效果 |
| `DeliberationOutcome` | id / runId / conditionProjections / flipConditions / dissentLog / assumptionLedger / disclaimer | 一个 run 至多一条，verdict 轮产出；append-only 事件留档；见 §3 概率禁令 |

### 2. API 面（10-api-and-events.md §核心 API 表新增行，ops 只增）

全部 workspace-scoped、`{ ok, data }` 信封、反枚举统一 `CASE_NOT_FOUND` 404；读面不携带 CSRF，写面 CSRF + `Idempotency-Key`：

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/workspaces/{workspaceId}/cases/{decisionCaseId}/deliberations` | 创建议会 run（body：主观因子声明[]、maxRounds≤5）；冻结因子快照 |
| `GET` | `/api/workspaces/{workspaceId}/cases/{decisionCaseId}/deliberations` | 列出该 Case 的议会锚点（时间倒序） |
| `GET` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}` | 读取 run 详情（因子、轮次、状态、完整待决提议/提名视图） |
| `GET` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/messages` | 分页读取转录 |
| `GET` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/events` | SSE 事件流（§4） |
| `POST` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/interventions` | 分类优先的用户介入：`interject \| challenge_witness \| declare_subjective_factor \| reopen_round`；非法分类拒绝（仿 RunResolution fail-closed） |
| `POST` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/proposals/{proposalId}/decision` | 用户采纳/驳回提议；accepted ⇒ 落引擎 override 并重算 |
| `POST` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/nominations/{nominationId}/decision` | 用户确认/拒绝主持提名；confirm ⇒ 创建主观因子并恢复 run |
| `GET` | `/api/workspaces/{workspaceId}/deliberations/{deliberationRunId}/outcome` | 读取条件化预估；未 complete 时诚实 404 |

### 3. Outcome 契约与概率禁令（17-product-design-v2.md 不确定性表达同步）

`DeliberationOutcome` 字段**固定**为：

- `conditionProjections[]`：每项 = 一个被采纳提议集下的引擎投影（`overrides` 引用 + `simulate()` 产出的 outcomeScore/verdict/flipThreshold）与条件描述；
- `flipConditions[]`：取自引擎 `topDrivers`/`flipValue` 的翻转条件；
- `dissentLog[]`：立场被推翻的持证人留档（factorId、原立场、被推翻依据）；
- `assumptionLedger[]`：全部因子的 provenance / evidenceStatus / 最终强度清单；
- `disclaimer`：固定文案"沙盘与议会不代表精确预测"。

**禁令（schema 级断言 + QA 电池）**：outcome、message、事件 payload 的任何字段与文案不得出现"成功概率""结论正确概率"或任何 0-1 概率化断言（AGENTS §7）。数值只允许是引擎产出的倾向得分/强度/翻转点。

### 4. SSE 事件面（10-api-and-events.md §SSE 事件 同步；AGENTS §9 增补）

新事件表 `DeliberationEvent`，信封逐字段镜像 `AnalysisEvent`（id / sequence / workspaceId / decisionCaseId / deliberationRunId / category / type / originMode / sourceOriginModes / createdAt / payload）：

- `category` 固定为 `deliberation.round`、`deliberation.message`、`deliberation.proposal`、`deliberation.nomination`、`deliberation.outcome`；`event:` 等于 category，`data:` 是完整信封。
- `sequence` 在单个 `deliberationRunId` 流内严格单调，服务端持久化时分配；支持 `Last-Event-ID` 重放。
- `originMode`/`sourceOriginModes` 诚实记录 live/fixture（§8），FIXTURE_MODE 下整套编排使用确定性夹具证人/主持，不得冒充实时结果。

### 5. 编排合同（09-simulation-engine.md 同步：议会是因子沙盘之上的推演层）

- 编排器是 worker 侧新 job kind（复用 `FOR UPDATE SKIP LOCKED` 队列 + heartbeat + attempt），**不是**第五类正式分析 Worker（AGENTS §7 四类职责不变）。
- 轮次协议：R0 opening（持证人对各自因子并行 structured output 发言：立场/主张影响/依据/对他者质疑）→ R1..n challenge（回应质疑、产出提议）→ verdict（主持合成 outcome）。轮间检查介入队列与用户决策；提名使 run 进 `awaiting_user`。
- **引擎裁决铁律**：一切数值（强度、投影、翻转点）只能由 `simulations/factor_sandbox.simulate()` 计算；智能体输出经 Pydantic schema 校验，失败至多一次修复重试，仍失败则丢弃并留痕（对齐 §8 strict tool call 纪律）。智能体不得自报数值结果。
- 预算硬上限：maxRounds ≤ 5、每轮发言数上限、单 run token 预算；超限即推进 verdict 并在 outcome 诚实注记。
- `reasoning_content` 瞬态纪律全量继承 §8。

### 6. 前端合同（11-frontend-spec.md 同步）

G 页新增"推演棋盘"区块（与因子沙盘、正式沙盘并列）：棋盘图（主观因子 = 虚线边框 + human 色 + Human 署名角标）、议会实况转录（SSE + Last-Event-ID 续读）、介入控制台、主观因子声明表单（可引用 Dossier assumption）、提名确认卡、提议账本（采纳/驳回即时引擎重算）、结果面板（固定免责声明）。状态全覆盖：loading / empty / preparing / running / awaiting_user / complete / error / fixture 标识。≤620px 实况面板折叠为只读流（§11 小屏只读概览）。
