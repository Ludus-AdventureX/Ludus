# CCR-20260719-002: 决策操作系统工程不变量、真实生命周期与 Agent Engine 合同

- Status: accepted
- Requested by: strategy analyst recommendation audit
- Contract owner: Product/Contract owner
- Date accepted: 2026-07-19
- Related plan: `26-decision-os-invariants-and-agent-engine-contract.md`

## Reason

现有计划已经具备版本化 Case、AnalysisRun、证据质量门、结构化报告、因果图和 Review，但没有完整落实以下责任边界：精确 SourceSpan、独立 Judgment、统一 Human/Analysis/Unknown 责任类型、PendingSignoff、人类签署、append-only DecisionRecord、显式 Cynefin gate、顶层 DeepAnalysis I/O 和九项独立验证职责。

原 `POST /cases/{caseId}/decisions` 可直接产生 `decided`，`DecisionRecord.decidedBy` 可空，Case 只有 `draft/active/decided/archived`，与“系统不能替人决定”的产品定义冲突。因此该变更属于发布阻断的 canonical 修正。

## Canonical Impact

- `06-data-model.md`：新增 ResponsibilityClass/Stamp、DecisionLifecycleStage、SourceRecord、SourceSpan、RunManifest、Judgment/Set、DissentRecord、SignoffRequest、DecisionLifecycleEvent；DecisionRecord 改为不可变签署记录。
- `07-agent-workflow.md`：加入 Cynefin 前置门、九 Validator Contract、工具拒绝表和责任边界。
- `08-deep-research-pipeline.md`：冻结 RunManifest，正式输入/输出改为 DeepAnalysisRequest/Result。
- `10-api-and-events.md`：移除直接决定创建流程，改为 signoff request + human sign；新增事件与错误码。
- `13-testing-and-acceptance.md`：加入三条红线、九 Validator、责任语义与 SourceSpan 测试。
- `17/18/21/23`、README、agent manifest、`decision-lab/AGENTS.md`：同步产品、实施、资产、容量和开发约束。
- Ways：新增 `hardtech-market-direction@1.1.0`，补 Cynefin、Judgment/Dissent、DeepAnalysisResult、SourceSpan 与 Validator schemas。

## Compatibility

- Backward compatible: 读取旧 Run/Report/Decision 可通过 migration adapter 保留。
- Breaking write change: 旧 `POST /cases/{caseId}/decisions` 停止接受新写入；新客户端必须使用 signoff request + sign。
- Migration required:
  - Case 旧 `active` 依据当前数据迁移为 `scoped|ready|running|review|pending_signoff`；旧 `decided` 迁移为 `decided`；旧 `archived` 写入 operational status；
  - 历史 DecisionRecord 回填签署主体时必须使用可验证的审计 actor；无法验证时标记 `legacy_unsigned` 且禁止作为新决定的合规样本，不能伪造签名；
  - 建立 DecisionRecord UPDATE/DELETE 拒绝机制和 supersession 关系；
  - Report 增加 FK/scope/publisher 约束；
  - SourceSpan 对旧数据允许 migration warning，但新写入强制。
- Generated client impact: 必须重新生成 OpenAPI snapshot、TypeScript types 和 Web client。

## Proposed Change

1. Case 主生命周期改为 `draft → scoped → ready → running → review → pending_signoff → decided → monitoring`；异常状态由 operational status / AnalysisRun 表达。
2. `pending_signoff → decided` 只允许授权人类用户通过签署 command 执行。
3. DecisionRecord 插入后不可修改；修订创建新记录并指向旧记录。
4. Report 必须绑定 qualifying Run；无 Run、Run 未 ready 或 validation blocker 存在时不得发布。
5. 正式分析使用冻结 RunManifest 和 DeepAnalysisRequest/Result，不使用聊天 `messages[]` 主接口。
6. Validation Worker 执行九个独立、版本化 Validator Contract；blocker fail-closed，不投票决定真伪。
7. `framework-selector` 的 Cynefin 语义进入 Ways 1.1.0 的显式 gate；chaotic/disorder 默认阻断正式长分析。

## Rejected Alternatives

- 九个常驻微服务或九个模型多数投票；
- Agent/Worker 直接拥有 sign/decide 工具；
- 通过前端按钮隐藏代替服务端授权；
- 继续让 `DecisionRecord.status` 表达可变生命周期；
- 无 Run 的模板报告或 fixture 报告；
- 只用颜色区分 Human/Analysis/Unknown。

- DB tests：FK/scope、签署 request、UPDATE/DELETE 拒绝、supersession 唯一性。
