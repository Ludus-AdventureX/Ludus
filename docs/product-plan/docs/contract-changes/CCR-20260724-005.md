## Reason

Task 3 delivered the auth (`app/auth/**`), security envelope/CSRF (`app/security/**`), and tenancy context/router (`app/tenancy/**`) modules inside the `case_api_data` write scope. Mounting routers into canonical `app.main`, registering shared error handlers, registering new error codes in doc-10, adding non-secret `AUTH_*` placeholders to `.env.example`, and regenerating canonical OpenAPI/TypeScript are all `contract_lead`-owned steps, so the lane stopped and raised this CONTRACT_CHANGE_REQUEST instead of editing those files. QA independently verified the mounting steps are sufficient and endorsed the request.

## Accepted decisions

1. `services/api/app/main.py` mounts `app.auth.routes:router` (5 endpoints already defined in doc-10: `GET /api/auth/csrf`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/session`) and `app.tenancy.routes:workspace_router`, and calls `app.security.envelope.register_error_handlers(app)`. Task 4+ workspace-scoped resource routers must be included into `workspace_router` so tenancy guarding holds by construction.
2. Doc-10 error-code table adds `AUTH_INVALID_CREDENTIALS` (401, anti-enumeration: unknown email and wrong password answer identically) and `WORKSPACE_NOT_FOUND` (404, uniform denial that never leaks existence). No other codes are added: `SESSION_REVOKED_OR_EXPIRED`, `CSRF_VALIDATION_FAILED`, `MEMBERSHIP_CAPABILITY_REQUIRED`, and `VALIDATION_FAILED` — flagged by QA for confirmation — were verified to already exist in the canonical table, so no second CCR is needed.
3. `.env.example` adds non-secret placeholders `AUTH_JWT_SECRET`, `AUTH_COOKIE_SECURE`, `AUTH_SESSION_TTL_MINUTES`, `AUTH_ALLOWED_ORIGINS`, matching `AuthSettings`. Per QA's open question: `AUTH_SESSION_COOKIE_NAME`, `AUTH_CSRF_COOKIE_NAME`, and `AUTH_CSRF_HEADER_NAME` are fixed contract values for P0, intentionally not documented as configurable; making them configurable would require a new CCR.
4. `packages/contracts/openapi.json` and `packages/contracts/src/types.gen.ts` are regenerated from the canonical builder after mounting; generated outputs remain read-only for all consumers.

## Canonical impact

- `services/api/app/main.py`: router mounting + error handler registration (this change).
- `docs/product-plan/10-api-and-events.md`: two new error-code rows (this change); auth endpoints were already canonical.
- `.env.example`: four `AUTH_*` placeholders (this change).
- `packages/contracts/openapi.json`, `packages/contracts/src/types.gen.ts`: regenerated to include the five auth endpoints and error envelope semantics.
- No schema, migration, model, event, or state-machine change; no new tables or enums.
