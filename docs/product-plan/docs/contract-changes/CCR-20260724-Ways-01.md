## Reason

The Ways lane delivered the agent runtime and five-lens contract seam but correctly stopped at two canonical gaps: no persisted `StrategicLensArtifact` entity exists (AGENTS section 7 requires server-injected identity, method snapshot, and Validation-gated `ready`), and no canonical `ConnectorStatus` enum exists (AGENTS section 8 fixes the seven-value set). Additionally, `18-detailed-development-plan.md` file lists for Tasks 7/8/10 disagreed with `agent-work-manifest.yaml` write scopes; the manifest is authoritative and the plan document is the defect.

## Accepted decisions

1. `ConnectorStatus` enters `services/api/app/types.py` as the sole canonical definition with exactly: `available | missing_credentials | invalid_credentials | rate_limited | quota_exhausted | provider_error | disabled`. All lanes import it; parallel enums or string-literal sets are forbidden.
2. `StrategicLensArtifact` ORM enters `services/api/app/models.py` (contract_lead-owned): server-injected `strategic_lens_artifact_id/workspace_id/decision_case_id/analysis_run_id/charter_id`, `lens_type` reusing the existing `StrategicLensType`, `producer_role` (`research|critic|synthesis`), `status` (`draft|ready|rejected`, default draft), method snapshot (`method_id/method_version/method_content_hash/prompt_version/schema_version`), `origin_modes[]`, non-empty `content_hash`, JSONB `payload`, JSON reference lists `claim_refs/evidence_refs/assumption_refs` (resolved and validated server-side before insertion), `validation_accepted_at`, `created_at`.
3. Database invariants follow the Task 19A hardening pattern: composite FKs `(workspace_id, decision_case_id)` -> decision_cases and `(workspace_id, decision_case_id, analysis_run_id)` -> analysis_runs; `ready` requires `validation_accepted_at` (CHECK); at most one `ready` artifact per `(workspace_id, analysis_run_id, lens_type)` via a partial unique index; drafts/rejected keep audit history.
4. Alembic revision `d7e2a91c5b48_add_strategic_lens_artifacts.py` (down_revision `c4a1f0b2d9e7`) creates the table and the three lens enums; the shared `origin_mode` enum is reused, never recreated; downgrade drops the table and lens enums only.
5. `18-detailed-development-plan.md` Task 7/8/10 file lists are repaired to match the manifest: connector provider adapters move from Task 7 to Task 8 (`case_api_data`); `app/analyses/**` items in Task 10 are annotated as task-09 `case_api_data` scope; `strategic_lenses/models.py` is removed in favor of the canonical ORM in `app/models.py`; canonical migrations are always landed by contract_lead.
6. No API surface change in this execution: no endpoint, no wire schema, no `packages/contracts/**` regeneration (drift check must stay clean). The lens HTTP read surface arrives with a later report/case API slice under its own router-mounting CCR step.
7. Persistence/report wiring ownership: the write path (server-side injection + schema validation + insert) is implemented in ways scope consuming this canonical model; Run/Report consumption belongs to case_api_data; router mounting to contract_lead. The current Ways integration round remains persistence-free; wiring unlocks only after this CCR lands on main.
